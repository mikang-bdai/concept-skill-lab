Skill

概念 03   SKILL.md可复用岗位 SOP

把"做某件事的最佳实践 + 工具调用 + 输出规范"打包成一个可复用的指令包，让 AI 在合适场景自动或手动调用。

生成于 2026-09-05 · 来源：项目级 Skill learn-a-concept · 源文件：notes/03-skill.md

1一句话定义

Skill 是一份结构化的指令文档，告诉 AI「当遇到 X 场景时，按这套工作流办事，按这个模板输出」—— 本质上是给 AI 的一份「岗位操作手册」。

2解决什么问题

场景：你经常让 AI 做某类任务（比如学概念、写周报、改代码），每次都重复讲一遍规则太啰嗦。

痛点：零散 prompt 难维护、跨会话丢失、不同人写的风格不一致、好的工作流没法沉淀复用。

不解决的后果：每次都从零讲背景，AI 输出质量参差不齐，好的方法论没人能复用。

3核心要点（5-8 条）

触发条件（WHEN）
什么场景下该用它 —— 写在 frontmatter 的 description 里。
工作流（HOW）
具体怎么分步执行 —— 主体内容里的步骤说明。
输出模板（WHAT）
最后长什么样 —— 模板代码块明确格式。
注意事项（CAVEATS）
哪些坑不能踩 —— 边界条件与正确性优先。
  • 通常以 SKILL.md 文件形式存储，项目级放 <项目>/.workbuddy/skills/<name>/，用户级放 ~/.workbuddy/skills/<name>/。
  • 核心价值是复用：写好一次，所有人和所有会话都能用，且输出风格一致。
  • 好的 Skill 要包含：清晰的描述、明确的步骤、确定的输出模板、明确的边界（不该做什么）。
  • 不只是"指令"——好的 Skill 会告诉 AI 用什么工具、遵循什么约定、避免什么坑。
  • 可演进：用着用着发现问题就改 SKILL.md，下次自动更聪明。
  • 粒度要合适：太粗（"帮我干活"）没用，太细（"如何输入一句话"）难维护。
  • 触发机制：有的是显式调用（learn-a-concept: Agent），有的是 AI 自动识别场景触发。

4常见误解

❌ 误解
"Skill = 系统提示词"
✅ 正确
System prompt 是全局偏好，Skill 是按场景触发的"专项手册"。
❌ 误解
"Skill 越多越好"
✅ 正确
Skill 多到互相重叠会让 AI 不知道该用哪个，反而降低效果。
❌ 误解
"Skill 一次写好就完事"
✅ 正确
Skill 是用出来的，要根据实际效果反复打磨。
❌ 误解
"Skill 跟代码无关"
✅ 正确
Skill 常常会调用工具（读文件、写文件、跑命令），跟代码强相关。
❌ 误解
"Skill 可以让 AI 学会新知识"
✅ 正确
Skill 只是给指令，不能改变模型本身的能力上限。

5跟其他概念的关系

Prompt：Prompt 是"一次性说的话"，Skill 是"可重复用的话术包"，Skill 通常被引用展开成 Prompt。
Agent：Skill 是 Agent 的"技能库"，Agent 在循环里决定什么时候用哪个 Skill。 → 详见
Workflow / SOP：Skill 是把人类 SOP"翻译"成 AI 能执行的指令版，本质是知识工程化。
Plugin / Tool：Plugin 是"AI 能调的功能"，Skill 是"AI 何时该怎么调"的指南，两者常配合使用。
RAG：Skill 告诉 AI "怎么做"，RAG 给 AI "做什么的资料"，分工不同。
大模型的上下文：Skill 加载后会被拼到 system prompt 里，间接决定上下文里"该按什么规则办事"。 → 详见

6一个例子 / 类比

把 Skill 想象成公司里的岗位 SOP（标准操作流程）：

  • 新人入职不靠老员工口口相传，而是看 SOP 文档
  • SOP 里写着：什么时候触发（"客户来投诉"）、怎么做（"先记录、再道歉、再升级"）、输出什么（"投诉处理单"）、哪些坑不能踩（"不要当场承诺赔偿"）
  • 写得好的 SOP，新人照做就能产出老员工 80% 的水平
  • Skill 就是给 AI 的 SOP：写得越具体，AI 输出越稳定

跟 Agent 的关系像：Skill 是工具箱里的扳手，Agent 是会用扳手的工人。工人决定什么时候用哪把扳手，扳手本身不管事。

7我真的懂了吗？（自检 3 题）

1. Skill 的四件套是什么？为什么缺一不可？
触发条件、工作流、输出模板、注意事项各自的作用。
2. 项目级 Skill 和用户级 Skill 怎么区分？分别什么时候用？
仓库根目录的 .workbuddy/skills/ vs 用户主目录的 ~/.workbuddy/skills/。
3. 为什么说"Skill 是一次写好就完事"是错的？
Skill 是用出来的，需要根据效果持续打磨。
