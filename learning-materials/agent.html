Agent

概念 01   AI自主行动工具调用

能自己拆活儿、自己动手、直到把事儿办成的 AI 角色。

生成于 2026-09-05 · 来源：项目级 Skill learn-a-concept · 源文件：notes/01-agent.md

1一句话定义

Agent 是一种有自主行动能力的 AI —— 它不只是回答，而是主动规划步骤、调用工具、循环执行，直到目标完成。

2解决什么问题

场景：你想让 AI 真正去干活，而不是只会说"我可以帮你"。

痛点：普通聊天 AI 只能产出文本，碰到"帮我把这 30 张表合并成一张""帮我订机票""帮我把代码改了跑通测试"这种需要"动手"的任务就抓瞎。

不解决的后果：所有动作都得你手动复制粘贴 AI 的输出、再换工具执行，效率被限制在「AI 给建议 → 人来落地」的单步循环里。

3核心要点（5-8 条）

  • 三件套：Agent = LLM 大脑 + 工具集 + 记忆 + 循环控制器，缺一不可。
  • 循环控制器是灵魂：观察 → 思考 → 行动 → 观察新结果 → 再思考……直到目标达成。
  • 工具是手脚：搜网页、读文件、写代码、调 API、发邮件，都是工具。
  • 记忆分两层：短期记忆（当前任务上下文）+ 长期记忆（跨任务沉淀）。
  • 跟 ChatBot 的区别：ChatBot 是"问一答一"，Agent 是"接目标、想办法、动手干"。
  • 能力上限 = LLM 规划能力 × 工具覆盖度，二者都要强才好用。
  • 多 Agent 协作：复杂任务拆给多个 Agent 各管一摊（Code + Test + Review）。
  • 失败模式：规划走偏、工具调错、死循环 —— 必须有终止条件和人工兜底。

4常见误解

❌ 误解
Agent = 高级聊天机器人
✅ 正确
聊天机器人"说话"，Agent"办事"。
❌ 误解
Agent 一定会自我学习
✅ 正确
多数 Agent 不更新模型参数，只是"更会用工具"。
❌ 误解
Agent = AGI
✅ 正确
Agent 是工程产物，AGI 是通用智能的远期目标，二者不等价。
❌ 误解
给 LLM 接几个 API 就叫 Agent
✅ 正确
必须有"目标 → 规划 → 工具调用 → 观察 → 迭代"的完整闭环。
❌ 误解
Agent 越复杂越好
✅ 正确
工具越多循环越长越容易跑偏，简单任务不需要复杂 Agent。

5跟其他概念的关系

LLM：LLM 是 Agent 的"大脑"，没有 LLM 就没有现代 Agent；但 LLM 单独存在时不是 Agent。
ChatBot / 对话系统：ChatBot 是被动应答的"嘴"，Agent 是主动办事的"手"。
Workflow / 流程：固定 Workflow 是写死的 if-else 链，Agent 是动态规划的"灵活流程"。
RAG（检索增强）：RAG 是 Agent 的一个常用工具（"查资料"），但 RAG 本身不是 Agent。
Copilot / AI 助手：Copilot 通常是"副驾驶"（人主导，AI 辅助），Agent 更像"自动驾驶"（AI 主导，人兜底）。
大模型的上下文：Agent 的"短期记忆"本质就是它的当前上下文，工具返回结果也会被追加到上下文里。 → 详见
Skill：Skill 是 Agent 的"技能手册"，告诉 Agent 在什么场景下用哪套工作流。 → 详见

6一个例子 / 类比

把 Agent 想象成一个新入职的实习生：

  • 你告诉他目标（"把这季度的销售数据做成可视化报表"）
  • 他会自己问"数据在哪""用什么工具""做成什么样"
  • 他会去翻数据库、跑脚本、画图表
  • 遇到问题会回来找你确认（"口径对不对？"）
  • 而不是等你一步步指挥

普通 ChatBot 像一本《百科全书》——你问啥它答啥，不会主动翻页。Agent 像一个会自己跑去图书馆查资料、回来给你做总结的助理。

7我真的懂了吗？（自检 3 题）

1. Agent 跟 ChatBot 的根本区别是什么？
从"主动/被动"和"说话/办事"两个维度答。
2. 一个最小的 Agent 需要哪三件套？
LLM、工具、还有一个关键的"控制循环"组件。
3. 为什么说"给 LLM 接几个 API 还不算 Agent"？
判断标准不是接了多少 API，而是有没有完整的闭环。
